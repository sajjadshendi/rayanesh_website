# راهنمای تحریریه و مدیریت محتوای رایانش

هر تغییر محتوایی یک تغییر در مخزن است. پس از ادغام در `main`، Cloudflare نسخهٔ تازهٔ سایت را می‌سازد. برای کار روزمره لازم نیست برنامه‌نویسی بدانید؛ فایل متن و اطلاعات کوتاه ابتدای آن را ویرایش می‌کنید. ورود مستقیم از یک پنل عمومی روی دامنه در این نسخه وجود ندارد.

## نقشهٔ فایل‌ها

| چه چیزی را تغییر می‌دهید؟ | محل |
|---|---|
| متن مقاله، شعر یا یادداشت | `src/content/articles/*.md` |
| معرفی نویسنده | `src/content/authors/*.json` |
| جلد، فهرست، شناسنامه و PDF هر شماره | `src/content/issues/*.json` |
| پروندهٔ اصلی، نوشته‌های منتخب و راه‌های تماس | `src/data/site.json` |
| جلدها | `public/covers/` |
| تصویر مقاله و عکس نویسنده | `public/images/` |
| فایل نشریه | `public/downloads/` |
| خوانش صوتی | `public/audio/` |
| نمونهٔ آماده برای ساخت محتوا | `docs/templates/` |

نام فایل‌ها شناسه و بخشی از نشانی صفحه است. نام انگلیسی کوچک با خط تیره انتخاب کنید؛ مثل `mahdi-alizadeh` یا `algorithms-and-networks`. عنوان داخل فایل می‌تواند فارسی باشد. شناسه را بعد از انتشار بی‌دلیل تغییر ندهید؛ لینک‌های قدیمی می‌شکنند. فایل‌ها باید UTF-8 باشند.

## روش ساده با خود GitHub

۱. مخزن را باز کنید و برای تغییر تازه شاخه‌ای مثل `editorial/issue-21` بسازید.
۲. برای ویرایش فایل موجود، فایل را باز کنید و دکمهٔ مداد را بزنید. برای افزودن فایل، از **Add file → Create new file** یا **Upload files** استفاده کنید.
۳. یکی از نمونه‌های `docs/templates` را کپی کنید و در مسیر صحیح، با نام جدید ذخیره کنید. فایل مقاله پسوند `.md` دارد؛ فایل شماره و نویسنده `.json` است.
۴. چند فایل وابسته، مانند نویسنده و مقاله و شماره، را در همان شاخه تکمیل کنید. لازم نیست تغییرهای ناقص را به `main` ببرید.
۵. Pull Request بسازید. بررسی `Validate magazine / validate` و در صورت فعال بودن، پیش‌نمایش Cloudflare را ببینید.
۶. عنوان، انتساب، نیم‌فاصله، ترتیب مطالب، لینک PDF و نمایش گوشی را بررسی کنید و سپس ادغام کنید.

Preview گیت‌هاب برای Markdown با نمایش نهایی سایت یکسان نیست؛ مثلاً ظاهر فرمول، راست‌به‌چپ و فونت را در پیش‌نمایش سایت ببینید. نمونه‌ها نام واقعی نویسنده و شمارهٔ موجود دارند تا ساختار معلوم باشد؛ هنگام کپی **نویسنده و شمارهٔ نوشتهٔ خودتان را جایگزین کنید**.

## روش محلی و ساخت فایل آماده

پس از نصب پروژه طبق README، می‌توانید این دستورها را اجرا کنید:

```bash
npm run new -- author new-writer
npm run new -- issue 21
npm run new -- article my-new-story
```

فایل هم‌نام بازنویسی نمی‌شود. مقاله و شمارهٔ ساخته‌شده پیش‌فرض `draft: true` دارند. محتوا را کامل کنید و سپس:

```bash
npm run validate
npm run dev
```

فایل شمارهٔ پیش‌نویس می‌تواند هنوز PDF نداشته باشد. شناسه‌های مقاله باید به نویسنده و شمارهٔ موجود اشاره کنند؛ ابتدا آن فایل‌ها را بسازید. برای انتشار، ابتدا داده‌ها و دارایی‌ها را کامل و `draft` مقاله و شماره را در یک تغییر هماهنگ `false` کنید.

## ۱. افزودن نویسنده

فایل `src/content/authors/new-writer.json`:

```json
{
  "name": "نام و نام خانوادگی",
  "bio": "معرفی کوتاه و تأییدشدهٔ نویسنده.",
  "avatar": "/images/new-writer.webp",
  "links": [
    { "label": "وب‌سایت شخصی", "url": "https://example.com" }
  ]
}
```

`name` و `bio` لازم‌اند. اگر عکس یا پیوند ندارید، همان کلید را حذف کنید یا `links` را `[]` بگذارید. عکس را در مسیر گفته‌شده بارگذاری کنید؛ تصویر ساختگی به نام فرد قرار ندهید. پیوند بیرونی باید HTTPS باشد. معرفی تاریخی مانند «سردبیر شمارهٔ هفدهم» را با سمت فعلی اشتباه نگیرید.

نویسنده وقتی حداقل یک نوشتهٔ منتشرشده داشته باشد، در فهرست و صفحهٔ نویسندگان ظاهر می‌شود. برای چند نویسندهٔ یک مقاله، چند شناسه را در `authors` وارد کنید. آمار نوشته‌ها خودکار محاسبه می‌شود.

## ۲. افزودن شماره یا ویژه‌نامه

فایل `src/content/issues/21.json` نمونه:

```json
{
  "title": "عنوان پرونده",
  "number": 21,
  "kind": "regular",
  "order": 210,
  "dateLabel": "ماه و سال انتشار",
  "description": "معرفی کوتاه شماره و موضوع آن.",
  "cover": "/covers/21.webp",
  "coverAlt": "توصیف محتوای تصویری جلد",
  "pdf": "/downloads/rayanesh-21.pdf",
  "pdfPages": 24,
  "pdfBytes": 1234567,
  "draft": true,
  "tocLabel": "فهرست مطالب",
  "toc": [
    { "title": "عنوان نوشتهٔ اول", "pdfPage": 3, "article": "my-new-story" },
    { "title": "عنوان نوشته‌ای که فعلاً فقط در PDF است", "pdfPage": 7 }
  ],
  "credits": [
    { "role": "سردبیر", "names": ["نام سردبیر همان شماره"] },
    { "role": "طراحی جلد", "names": ["نام طراح"] }
  ]
}
```

این اعداد نمونه‌اند؛ باید از فایل واقعی خودتان گرفته شوند. برای ویژه‌نامه `kind` را `special` بگذارید، کلید `number` را می‌توانید حذف کنید و نام فایل را مثلاً `nowruz-1406.json` بگذارید.

| فیلد | معنی |
|---|---|
| `title` | عنوان نمایش‌داده‌شدهٔ شماره |
| `number` | شمارهٔ رسمی؛ برای `regular` اجباری |
| `order` | ترتیب آرشیو؛ عدد بزرگ‌تر جلوتر می‌آید و نباید تکراری باشد |
| `dateLabel` | تاریخ نمایشی فارسی؛ اختیاری، تاریخ نامعلوم را حدس نزنید |
| `description` | شرح کوتاه برای صفحه و موتور جست‌وجو |
| `cover` / `coverAlt` | مسیر جلد و توضیح برای دسترس‌پذیری |
| `pdf` | مسیر فایل یا لینک مستقیم HTTPS |
| `pdfPages` | تعداد صفحات واقعی فایل PDF |
| `pdfBytes` | اندازهٔ دقیق فایل به بایت |
| `draft` | `true` برای منتشرنشدن صفحهٔ شماره؛ پیش از انتشار صریح تعیین کنید |
| `tocLabel` | می‌تواند «فهرست مطالب» یا «نوشته‌های منتخب» باشد |
| `toc` | آرایهٔ مدخل‌ها به ترتیب مورد نظر تحریریه |
| `credits` | نقش و نام همکاران **همان شماره** |

هر مدخل فهرست، یک `title` و `pdfPage` دارد. اگر متنش در سایت آماده است، `article` را با شناسهٔ فایل مقاله اضافه کنید. در غیر این صورت این کلید را حذف کنید؛ لینک مستقیماً PDF را باز می‌کند. مدخل نباید به مقالهٔ پیش‌نویس یا مقالهٔ شمارهٔ دیگری اشاره کند.

`pdfPage` از **۱** و از اولین صفحهٔ فایل شروع می‌شود. مثلاً در یک PDF با جلد و شناسنامه، صفحهٔ چاپی ۱ ممکن است صفحهٔ ۳ فایل باشد. شمارهٔ بیستم به صورت صفحات روبه‌روست؛ به تعداد صفحات نمایشگر PDF توجه کنید.

برای گرفتن حجم دقیق فایل، در ریشهٔ پروژه:

```bash
node -e "console.log(require('node:fs').statSync('public/downloads/rayanesh-21.pdf').size)"
```

عدد خروجی را در `pdfBytes` بگذارید. اگر PDF را جایگزین کردید، این عدد هم باید تغییر کند.

## ۳. افزودن مقاله یا یادداشت

فایل `src/content/articles/my-new-story.md`:

```yaml
---
title: "عنوان نوشته"
description: "معرفی کوتاهی که در فهرست نوشته‌ها دیده می‌شود."
authors: [new-writer]
issue: "21"
topics: [culture, literature]
order: 1
draft: true
format: article
edition: full
pdfPage: 3
publishedAt: "2026-09-20"
---
```

بلافاصله پس از خط `---` پایانی، متن Markdown را بنویسید؛ داخل فایل واقعی، کادر سه‌بک‌تیکی بالای مثال را کپی نکنید.

- `authors`: یک یا چند شناسهٔ نویسنده؛ مانند `[first-writer, second-writer]`.
- `issue`: شناسهٔ فایل شماره. برای شناسه‌های عددی حتماً کوتیشن بگذارید: `"21"`.
- `topics`: یک یا چند مورد از `culture`، `literature`، `campus`، `science`.
- `order`: ترتیب مقاله در شماره؛ ترتیب فهرست `toc` نیز مستقل و مطابق چیدمان تحریریه است.
- `draft`: تا پیش از آماده شدن `true`؛ برای انتشار `false`. حذف این کلید از مقاله نیز پیش‌فرض پیش‌نویس است.
- `format`: برای نثر `article` و برای شعر `poem`.
- `edition`: اگر تمام متن منتقل شده `full`؛ اگر فقط بخشی آمده `excerpt`. در حالت گزیده، سایت پیوند متن کامل PDF را نشان می‌دهد.
- `publishedAt`: تاریخ واقعی میلادی `YYYY-MM-DD`، اختیاری. سایت آن را شمسی نمایش می‌دهد. اگر تاریخ دقیق معلوم نیست، حذفش کنید. گذاشتن تاریخ آینده، انتشار را زمان‌بندی نمی‌کند؛ کنترل انتشار با `draft` و ادغام شاخه است.

اطلاعات بالای مقاله YAML است: بعد از `:` فاصله بگذارید، از Tab استفاده نکنید و عنوان دارای `:`، `#` یا نشانه‌های خاص را داخل کوتیشن بگذارید. کلید ناشناخته و غلط املایی فیلدها باعث شکست build می‌شود تا خطا پنهان نماند.

## ۴. نوشتن متن، تصویر، شعر و مقالهٔ علمی

هر پاراگراف را با یک خط خالی جدا کنید. با `##` عنوان بخش و با `###` زیربخش بسازید. عنوان اصلی صفحه از `title` گرفته می‌شود؛ `#` داخل متن مجاز نیست.

```markdown
## عنوان بخش

متن عادی با **تأکید پررنگ** و *تأکید ملایم*.

> یک نقل‌قول کوتاه؛ منبع آن را هم ذکر کنید.

- مورد اول
- مورد دوم

[نوشتهٔ مرتبط](/articles/salam-rafigh/)

[منبع بیرونی](https://example.com/article)

![شرح دقیق تصویر](/images/my-story-photo.webp)

جمله‌ای با پانویس.[^source]

[^source]: توضیح یا منبع پانویس.
```

برای تصویر شاخص، در بخش اطلاعات مقاله این سه کلید اختیاری را اضافه کنید:

```yaml
image: /images/my-story-photo.webp
imageAlt: "توصیف آنچه در تصویر دیده می‌شود"
imageCredit: "نام عکاس یا منبع تصویر"
```

مسیر وب با `/images/` شروع می‌شود، هرچند فایل روی دیسک داخل `public/images/` است. فایل تصویر محلی و با پسوند PNG، JPEG، WebP، AVIF یا GIF باشد. تصویر از سایت دیگر مستقیماً وارد نکنید؛ علاوه بر حق استفاده، کیفیت، امنیت و حریم خصوصی را کنترل کنید. توضیح تصویر اجباری است.

برای شعر `format: poem` بگذارید. برای شکست سطر، در انتهای هر مصراع **دو فاصله** و سپس Enter بزنید؛ میان بندها خط خالی بگذارید. پیش‌نمایش را بررسی کنید تا شکست سطرها درست بمانند. محتوای اصلی صفحه همچنان متن قابل انتخاب است، نه عکس از شعر.

کد را میان سه بک‌تیک و نام زبان قرار دهید:

````markdown
```python
def square(number):
    return number * number
```
````

جهت کد خودکار چپ‌به‌راست است. کد بلند در محدودهٔ خودش اسکرول می‌شود و عرض کل صفحهٔ موبایل را نمی‌شکند. فرمول با KaTeX در زمان build ساخته می‌شود:

```markdown
فرمول درون جمله: $x^2 + y^2$.

$$
\hat{f}(x) = \min_{1 \le j \le d} C_{j,h_j(x)}
$$
```

دستورهای ناسازگار KaTeX یا محتوای فعال مجاز نیست. جدول Markdown نیز پشتیبانی می‌شود و در موبایل داخل ناحیهٔ جداگانه پیمایش می‌شود:

```markdown
| روش | حافظه | توضیح |
|---|---|---|
| روش اول | کم | شرح کوتاه |
| روش دوم | بیشتر | شرح کوتاه |
```

**HTML خام، MDX، `<script>`، iframe و کد اجرایی در متن پذیرفته نمی‌شود.** برای نمودار، خروجی تصویری خوانا با شرح و منبع قرار دهید. افزودن کامپوننت تازه یک تغییر کد است و باید جداگانه بازبینی شود.

## ۵. خوانش صوتی

فایل را مثلاً در `public/audio/my-new-story.mp3` بگذارید و در اطلاعات مقاله اضافه کنید:

```yaml
audio:
  src: /audio/my-new-story.mp3
  reader: "نام خوانشگر"
```

نام خوانشگر از نویسنده جداست. متن خوانش باید در همان صفحه موجود باشد. فایل به صورت خودکار پخش یا پیش‌بارگیری نمی‌شود. فرمت‌های قابل ثبت `mp3`، `ogg`، `m4a` و `wav` هستند؛ MP3 معمولاً انتخاب ساده‌تری برای توزیع است. حجم هر فایل باید زیر ۲۵ MiB باشد. چون فایل صوتی از شمارهٔ بیستم تحویل داده نشده، برای QRهای داخل آن پخش‌کنندهٔ ساختگی ایجاد نشده است.

## ۶. تغییر صفحهٔ نخست و اطلاعات عمومی

در `src/data/site.json`:

| فیلد | کاربرد |
|---|---|
| `featuredIssue` | شناسهٔ شمارهٔ اصلی صفحهٔ نخست |
| `heroTitle` | پرسش یا تیتر اصلی |
| `heroDescription` | معرفی پرونده |
| `heroImage`، `heroImageAlt`، `heroImageCredit` | تصویر اصلی، شرح و اعتبار آن |
| `featuredArticles` | شناسهٔ نوشته‌های منتخب به ترتیب نمایش |
| `tagline` | جملهٔ کوتاه هویتی |
| `contactEmail` | ایمیل عمومی تحریریه، اختیاری |
| `socialLinks` | آرایهٔ پیوندهای رسمی، مشابه پیوند نویسنده |

شمارهٔ اصلی و نوشته‌های منتخب باید منتشرشده باشند. سه مدخل اول `toc` شمارهٔ اصلی کنار پروندهٔ صفحهٔ نخست نمایش داده می‌شوند. آرشیو جلدها خودکار مرتب می‌شود. اطلاعات اصلی سایت را در این فایل تغییر دهید؛ برای هر شماره نیاز به دستکاری layout نیست.

## ۷. مدیریت فایل و امنیت تحریریه

همهٔ فایل‌های `public/` عمومی‌اند، حتی اگر به آن‌ها لینک نداده باشید یا مقاله `draft: true` باشد. فایل محرمانه، پیش‌نویس حساس، نسخهٔ دارای اطلاعات خصوصی، سند شناسایی، فایل Word داخلی، کلید و توکن را آنجا نگذارید. `draft` جلوی ساخت صفحه و ورود متن به جست‌وجو/RSS را می‌گیرد؛ ابزار کنترل دسترسی به فایل نیست.

نسخهٔ اصلی PDF را برای آرشیو تحریریه نگه دارید. برای وب نسخهٔ جدا و سبک‌تر بسازید؛ تعداد صفحات، کیفیت متن، رنگ و QRها را پس از فشرده‌سازی بررسی کنید. محدودیت ۲۵ MiB به معنی ۲۶٬۲۱۴٬۴۰۰ بایت است. نسخهٔ وب شمارهٔ بیستم به این سقف نزدیک است؛ جایگزین حجیم‌تر باید دوباره بررسی شود. لینک PDF بزرگ می‌تواند HTTPS بیرونی باشد، ولی هزینه، دسترس‌پذیری و محرمانگی آن میزبان را جداگانه بررسی کنید.

پیش از انتشار فایل دریافتی، اسکن بدافزار و کنترل نبودن اطلاعات شخصی یا فرادادهٔ نامناسب انجام دهید. تغییر فایل قدیمی با همان نام می‌تواند مدتی تحت تأثیر cache باشد؛ برای ویرایش مهم فایل نام تازه بدهید و مسیرها را به‌روز کنید. از Git LFS برای این نسخه استفاده نشده است؛ فایل pointer به جای PDF نباید در خروجی منتشر شود.

اگر شناسهٔ منتشرشده را عوض کردید، علاوه بر همهٔ ارجاع‌ها، در `public/_redirects` یک مسیر انتقال اضافه کنید:

```text
/articles/old-name/ /articles/new-name/ 301
```

بدون redirect، لینک‌های قبلی از سایت‌های دیگر از کار می‌افتند. حذف انتشار از نسخهٔ جدید، نسخه‌های قدیمی preview، cache و تاریخچهٔ Git را لزوماً پاک نمی‌کند. برای حذف محتوای حساس، راهنمای امنیت و دسترسی‌های Cloudflare را هم بررسی کنید.

## کنترل پیش از انتشار

- نام و رضایت نویسنده، منبع تصویر و صحت نقل‌قول‌ها بررسی شده باشد.
- `draft`، شناسه‌ها، تاریخ واقعی و صفحهٔ PDF درست باشند.
- لینک و فهرست، نام خوانشگر و وضعیت متن کامل/گزیده درست باشد.
- `npm run validate` موفق باشد؛ هشدار امنیتی وابستگی‌ها نادیده گرفته نشود.
- در پیش‌نمایش موبایل، عنوان بلند، جدول، کد، شعر و دکمهٔ دریافت PDF بررسی شوند.

جزئیات امنیت حساب و انتشار در [SECURITY.md](../SECURITY.md) آمده است.
